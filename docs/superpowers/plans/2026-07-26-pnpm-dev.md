# Unified `pnpm dev` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add root `pnpm dev` / `pnpm dev:seed` so one command brings up Postgres, applies migrations (and optionally seed), then runs Nest API + Vite web together via `concurrently`.

**Architecture:** Sequential prep (`db:up` → `scripts/wait-for-postgres.sh` → `prisma migrate deploy`) then `concurrently` for `dev:api` + `dev:web`. Seed is a separate script that inserts `prisma:seed` between prep and apps. Existing single-process scripts stay unchanged.

**Tech Stack:** pnpm workspaces, Docker Compose (`postgres` service), Prisma migrate deploy, `concurrently`, Nest `start:dev`, Vite.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-26-pnpm-dev-design.md`
- `pnpm dev` starts: Postgres (Compose) + migrate + Nest API + Vite web
- Seed: **not** on every `dev`; separate `pnpm dev:seed` seeds then starts apps
- App orchestration: `concurrently` (root `devDependency`) with `[api]` / `[web]` prefixes
- Migrate command: `prisma migrate deploy` (non-interactive)
- Env files: manual (`cp` from examples); `dev` does **not** create `.env`
- Postgres after Ctrl+C: stays up; tear down via existing `pnpm db:down`
- Out of scope: auto-copy `.env`, full Docker API/web stack (`stack:up`), codegen, Playwright
- Keep `dev:api` and `dev:web` unchanged for single-process work

### Task 1: `scripts/wait-for-postgres.sh`

**Files:**
- Create: `scripts/wait-for-postgres.sh`

**Interfaces:**
- Consumes: Docker Compose project with service name `postgres` (user `bookmark`, db `bookmark`)
- Produces: executable script; exit `0` when ready; exit `1` on timeout; env overrides `TIMEOUT_SECONDS` (default `60`)

- [ ] **Step 1: Create the wait script**

```bash
#!/usr/bin/env sh
set -eu

TIMEOUT_SECONDS="${TIMEOUT_SECONDS:-60}"
COMPOSE="docker compose"
deadline=$(( $(date +%s) + TIMEOUT_SECONDS ))

echo "Waiting for postgres to accept connections..."
while true; do
  if $COMPOSE exec -T postgres pg_isready -U bookmark -d bookmark >/dev/null 2>&1; then
    echo "Postgres is ready."
    exit 0
  fi
  if [ "$(date +%s)" -ge "$deadline" ]; then
    echo "Timed out waiting for postgres after ${TIMEOUT_SECONDS}s" >&2
    $COMPOSE ps postgres >&2 || true
    $COMPOSE logs --tail=50 postgres >&2 || true
    exit 1
  fi
  sleep 1
done
```

- [ ] **Step 2: Make executable**

```bash

```

- [ ] **Step 3: Verify ready path (Postgres up)**

```bash

```

Expected: prints `Postgres is ready.` and exits `0`.

- [ ] **Step 4: Verify timeout path**

Expected: timeout message on stderr; `exit=1`. (If Compose still has a leftover healthy container, force `docker compose down` first.)
